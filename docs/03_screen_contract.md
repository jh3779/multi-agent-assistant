# 03. 화면 계약 (Screen Contract) — 채팅 UI

> 인터뷰 영역 5 정리 — 화면별 "무엇을 반드시 보이고, 무엇을 할 수 있는가" · 상태: draft

## SCR-001 · 채팅 화면
- **목적:** 사용자가 어시스턴트에게 텍스트·파일로 질문하고, 도구 호출 과정과 최종 답변을 실시간으로 확인
- **진입:** 페이지 최초 로드(다른 화면에서 오는 경로 없음)
- **가시 의무(반드시 보여야 하는 것):**
  - 메시지 입력창 + 전송 버튼
  - 파일 업로드 영역(드래그 가능하다는 시각적 표시)
  - 메시지 로그(질문/답변 말풍선, 시간순)
  - 진행 중인 도구 이름/상태 라인
- **행동(사용자가 할 수 있는 것):**
  - 텍스트 입력 → 전송(Enter 또는 버튼) → 메시지 로그에 즉시 추가
  - 파일 드래그 또는 파일 선택 → 대상 포맷 지정 → 업로드
  - 변환 결과 파일 다운로드
  - (Could) 새 대화 시작 → 화면의 메시지 로그 초기화
- **상태별 표현:**
  | 상태 | 표현 |
  |------|------|
  | empty | "무엇을 도와드릴까요" 안내 문구 + 입력창 포커스 |
  | sending | 전송 버튼 비활성화, 사용자 메시지 즉시 로그에 추가 |
  | tool-active | "🔧 {tool_name} 호출 중..." 상태 라인(SSE `tool_start`/`tool_end` 이벤트 기반) |
  | streaming | 답변 텍스트가 토큰 단위로 이어붙여짐 |
  | uploading | 업로드 진행 표시(파일 크기에 따라 스피너) |
  | error | 에러 메시지 + 원인 텍스트(예: "지원하지 않는 포맷") + 재시도 버튼 |
- **금지:** 이전 대화 맥락을 서버에 보내거나 참조하지 않는다 — **멀티턴 아님, 매 요청은 완전히 독립적**. 로그인/사용자 식별도 하지 않는다.
- **근거:** REQ-F-001~006
